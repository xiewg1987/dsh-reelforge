## 1. 核对方法与判定口径

### 1.1 抽取方式

- **设计侧**：Node 脚本解析 SVG 的 `<text>` 节点（取 `x` / `y` / `font-size` / `fill`），按 `y` 升序还原版面分区；再用 `<rect>` 抽卡片几何与按钮尺寸。17 块板的 Footer 几何**完全一致**（`rect x=0 y=830 w=560 h=70` + 主按钮 `x=436 y=846 w=104 h=32`），**只有文案不同** —— 这是 S1 的直接证据。
- **实现侧**：静态阅读 `src/client/**` 全部 13 个片段与 `src/host/projection.js`，全部结论带 `文件:行号`。
- **交叉核对**：另外两个独立子任务分别逐板核 01–09 与 10–17+架构图；本表的每条结论都标注了是否经主流程复核。

### 1.2 定性口径

| 定性 | 含义 |
| --- | --- |
| `缺失` | 设计稿明写了，实现里没有 |
| `结构不符` | 设计稿是一套模式，实现是另一套 |
| `字段缺失` | 区块在，但字段不全 |
| `文案不符` | 块在、文案在，但文字与设计稿不一致 |
| `顺序或位置不符` | 内容对，但放在别处 |
| `交互缺失` | 设计稿要求可点/可写，实现是只读 |
| `超出设计稿` | 实现有、设计稿没有（也列出来，请 owner 拍板） |

### 1.3 刻意不判为差距

- 画板右侧 3px 滚动条：实现用原生 `overflow-y:auto`，属浏览器 chrome。
- 像素级尺寸差异：设计稿是示意图，只对**内容、字段、模式、顺序、交互**判差距。

**症状（真机）**：工作台日志页点「回滚」→ 宿主 ask 授权面板弹出 → 点「允许一次」→ 工具返回 `{"ok": true, "restored": 1}` → **界面一动不动**（章节还是 2 章）。

**根因**：核心层的契约明写「`row === null` 表示**删除该行**」，但宿主接线层（`src/host/changelogStore.js` 的 `writeRow`）把 `null` **降级成 `{}`** 再走 upsert —— 而 `chapter.upsert` 是**合并**语义，空对象合并不进去 ⇒ **回滚什么都没改**，工具却回报成功。

**修法**：

1. `src/host/projection.js`：新增四个**删除类补丁** `chapter.delete` / `shot.delete` / `asset.delete` / `project.delete`（以前**没有任何补丁能删掉一行**）。
2. `src/host/changelogStore.js`：`value === null` ⇒ 走删除补丁；否则走原来的 upsert/set。
3. `src/core/changelog.js` 的 `detectDrift`：漂移 = 当前行**既不是 `after` 也不是 `before`**。理由：漂移保护要挡的是「覆盖别人的改动」；「当前行 == `before`」要么是变更还没落地，要么是**已经被回滚掉了** —— 两种都不是「被别人改过」。不这么判的话，回滚「新建」之后该行不存在（`current = null` = `before`）会被误判成漂移 ⇒ 日志页挂出假的「已漂移」卡片，再点一次还会撞 409。

**实机复测证据**：回滚「新建章节 1」⇒ 章节页副标 `《夜航船》· 2 章 · 0 镜` → `《夜航船》· 1 章 · 0 镜`，章节页正文只剩「第2章」，控制台 0 错。

#### 11.8.3 顺带修掉 1 处「点了没反应」

日志页给每条变更都挂一个可点的「回滚」，**包括「新建项目 project」** —— 而项目层是**永不可回滚**的硬约束（没有删除项目的 API ⇒ 403）。实机点到它：工具报 403，用户在界面上只看到「什么都没发生」。
