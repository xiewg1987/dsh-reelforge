## 2. 范围内

### 2.1 探测（preflight）——**范围由运行位置决定**（§7.1）

照 infinite-creation `stages.js` 的结构：**每个阶段跑之前先探自己需要的东西，探不过就不开跑**。

| 能力 | 探测方式 | 门槛 | 谁需要 |
| --- | --- | --- | --- |
| ComfyUI 服务可达 | `GET /system_stats` | 不通 → 该阶段不可用 | `image` `tts` `video` |
| ComfyUI **CK 版本** | 读 `system_stats` 里的 comfy-kitchen 版本 | `>= 0.2.36` 判坏 | `image` 必须**不带** CK 注意力；`video` 建议带（实测快 2.7×） |
| GPU 与**显存余量** | `nvidia-smi` / `Get-CimInstance Win32_VideoController` / ComfyUI 上报的 `vram_free` | `video` 阶段需 **≥ 8GB** | `video` |
| ffmpeg / ffprobe 存在与版本 | `ffmpeg -version` | 缺 → 无法合成 | `video` 尾段（T4 用） |
| 可用编码器 | `ffmpeg -encoders` 过滤 `libx264` / `h264_nvenc` / `aac` | 无 `aac` → 无声 | 合成（T4 用） |
| 本地磁盘余量 | 目标工作区所在卷 | 不足 → 不开跑 | 全部 |
| LLM 通道可达 | `/models` 探活（5s 超时） | 不通 → `llm` 阶段不可用 | `llm` |
| provider 可达性（云端档） | 轻量 ping | 失败 → 该 kind 不可用 | 云端档全部 |
| **视频后端硬约束** | 规格声明 | 静态 | `r2v` |

**范围规则**：选**本地**跑 9 项（7 项本地专属 + 2 项两边都要的 LLM 通道与规格集）；选**云端**只探 provider 可达性 + 视频后端硬约束 + LLM 通道。**混检是浪费**，且会让「本机不具备本地生成条件」这种结论在用户根本不想本地跑的时候跳出来吓人。

**探测结果落插件状态，不进会话日志**（R2）。见画板 `04-RF/DeviceCheck`。

### 2.2 规格执行器（§8.1）

`src/workflows/{spec,runner}.js`。执行器是**四步**：

```text
克隆 sourceFile
  → 按 roles 写参数（map 做枚举翻译：'9:16' → '9:16 (Portrait Widescreen)'）
  → bindMedia 绑定参考素材
  → pruneWorkflow 裁剪
  → 提交
```

**`prune` 的语义（比「点名删除」聪明）**：

1. 先按 `spec.prune` 点名删；
2. 再从 `outputs` 根节点**反向做可达性遍历**，保留可达节点，其余删除；
3. 最后清掉指向已删节点的**悬空连线**。

可达性裁剪**自动解决**「prompt 被直写后 LLM 扩写链变成孤立节点」的问题——**不需要手写 prune 清单**。

**`bindMedia` 的两种形态**：

| 形态 | 做法 |
| --- | --- |
| ① `mediaField` / `typeField` | `media_1` + `media_type_1` 形式 |
| ② `fieldsByType` | 按类型各自编号，**从 0 起**，对应 H3 的 `ref_images.ref_image_0` |

优先复用 `reusePool` 里的模板 loader 节点；不够则新建（节点 id 用 `String(1000 + i)`）；最后**删除未被引用的模板占位 loader**。

### 2.3 五种 kind（§8.1）

| kind | 输入 | 输出 | 谁在用 |
| --- | --- | --- | --- |
| `t2i` | 文本提示词 | 图片 | 人物 / 场景 / 道具参考图 |
| `i2i` | 文本 + 参考图 | 图片 | 换装 / 年龄变体 / 图像编辑 |
| `r2v` | 文本 + 参考图 + 参考音 | **带语音的视频** | 逐镜片段 |
| `tts` | 台词 + 音色描述 | 音频样本 | 角色音色 |
| `music` | caption + lyrics + 时长 | 音频 | 章节背景音乐 |

### 2.4 两种执行位置（§8.1）——**同一批 kind，两套 `sourceFile`**

| kind | 云端（RunningHub） | 本地 · nvidia | 本地 · amd |
| --- | --- | --- | --- |
| `t2i` | `runninghub_krea2_t2i` | `krea2_hyperreal_t2i` | `qwen_image_2_1_t2i_gguf` |
| `i2i` | `runninghub_qwen_image_edit_2511_i2i` | `qwen_image_edit_2511_i2i` | `qwen_image_2_1_i2i_gguf` |
| `r2v` | `runninghub_minimax_h3_r2v` | `minimax_h3_r2v` | `minimax_h3_r2v_gguf` |
| `tts` | `runninghub_qwen3_tts_voice_design` | `qwen3_tts_voice_design` | `qwen3_tts_voice_design_gguf` |
| `music` | `runninghub_minimax_music3` | `minimax_music3` | `minimax_music3` |

**取用顺序**：provider = `runninghub` → 直接用云端列（**忽略硬件预设**）；否则依次取 `用户配置.workflows[kind]` → 本地 nvidia 列 → 本地 amd 列。

> ⚠️ **这张表不是「本地一档、云端一档」**。本地与云端**支持同样的五种 kind**，差异只在**跑在哪、计不计费、受什么约束**。这是 v4 修正过的前提错误，别再犯。

**云端三个 provider**：RunningHub（`standard` / `plus` 两档）、在线 API（厂商直连）、DSH 通道（宿主已验证模型）。见画板 `03-RF/RunMode`。

### 2.5 本地 ComfyUI 档的实现约束（§8.6）

- **CK 版本硬门槛 `>= 0.2.36`**。版本比较只比**前 3 段且必须是纯数字段**——`0.2.37rc1` 会被判「读不准」→ **保守判坏**。
- **`image` 阶段必须不带 CK 注意力**——带了直接抛错并提示换启动脚本。
- **`video` 阶段建议带** CK 注意力（实测快 **2.7×**）；没带**只 warn 不拦**。
- **AMD 档**：默认每 **3 次**生成后调 `/free` 释放显存；`image` / `i2i` / 换装 / 音色 / 视频**全部计入**计数（AMD Dynamic VRAM 下任意连续生成都会逐步变慢）。未启用 Dynamic VRAM 时界面要提示关闭。

### 2.6 四阶段编排（§8.4、F7）

**阶段模型（固定）**：

```text
STAGES = [ llm, image, tts, video ]
```

| 阶段 | 做什么 | 依赖 |
| --- | --- | --- |
| `llm` | 写人物圣经 / 风格指南 → 拆镜 → 写视频提示词 → 写入（写入即校验） | 需要 LLM 通道 |
| `image` | 人物 / 场景 / 道具参考图 + 服装与年龄变体 | 产出后续两阶段的参考图 |
| `tts` | 角色音色样本 | **软依赖**：缺失时视频降质，**界面必须标出来** |
| `video` | 逐镜出片 → 自审重试 → 背景音乐 → 合成 → 字幕 | **硬依赖 image**：没有参考图**直接抛错** |

**六条编排纪律**：

1. **固定顺序串行**——**不按用户勾选的顺序**跑。
2. **硬依赖 = 报错**，软依赖 = 降质但**必须说出来**。
3. **`llm` 与渲染阶段双向互斥**（`renderDisabled` / `llmDisabled`）。
4. **并发**：video **1** / runninghub **1** / image **2**。
5. **队列等待上限 120 分钟**。
6. **不做自动拆批**——显存不够就**明说不够**（见 §2.7）。

### 2.7 显存门槛：直接拒，不拆批（§7.1）

- 含 `video` 阶段 → 需 **8GB**；否则 **4GB**。
- **不足 → 明确拒绝该阶段**并说清「当前 6GB，video 阶段需 8GB」。
- **不做「自动拆批」**：upstream 其实也没有自动拆批，只有「门槛检查 + 全局并发闸门」；**显存不够就明说不够**。

### 2.8 幂等与断点续跑（§8.4）

- **内容指纹**：同一镜的「影响结果的内容字段」算指纹；指纹命中 → **不重复生成、不重复计费**。
- **只改依赖字段时才重算**——拿旧值重算会把历史遗留的超速台词变成整行不可编辑。
- **断点续跑**：从上次中断的阶段/镜继续，已完成的不重跑。
- **提示词改写最多 2 次尝试**，且**必须保留全部 `__MINIMAX_H3_REF_N__` 占位符**。

### 2.9 音频是两件事（§7.5）

**音色设计（`tts`）与背景音乐（`music`）是两个独立阶段**，不要混：

| | 音色设计 | 背景音乐 |
| --- | --- | --- |
| 输入 | 台词 + 音色描述 | caption + lyrics + 时长 |
| 输出 | 角色音色样本 | 章节 BGM |
| 归属阶段 | `tts` | `music`（在 `video` 尾段） |
| 谁引用 | **只有说话角色** | 整章 |

### 2.10 触发类工具的授权（§4.4 R4）

`run_stage` / `regenerate_shot` / `assemble_chapter` / `rollback` 四个工具会**烧钱、占显存**，一律走宿主 `ask` 人工授权（`tools/pre-execute` 返回 `ask`）。

## 6. 关键契约速查

**F5 `WorkflowSpec`**：`{id, kind, name, description, sourceFile, roles, media?, outputs, prune?}`。
**F6 `resolveRefs`**（T2 产出）：`{images[], audios[], tags[], order[], warnings[]}`——**只消费**。
**F7 阶段模型**：`[llm, image, tts, video]`，固定串行；**video 硬依赖 image、软依赖 tts**。
**F8 枚举**：`constants.js`。

**CK**：`>= 0.2.36`；`image` 禁带 CK 注意力，`video` 建议带。
**显存**：含 video `8GB`，否则 `4GB`。
**并发**：video `1` / runninghub `1` / image `2`；队列上限 `120min`。
**参考上限**：图 `≤9`、音视频 `≤3`；占位符 `__MINIMAX_H3_REF_N__`（N 从 1 起）。
**时长**：`1…15`s，默认 `5`s；对白 `5.5` 字/秒；每镜说话人 `≤2`。

## 7. 风险与已知坑

| # | 坑 | 后果 | 怎么躲 |

| 12 | 触发类工具不授权直接跑 | **烧钱、占显存**，用户不知情 | 四个工具一律走 `ask` |

3. src/workflows/{comfyui,runninghub,dshMedia}.js：本地 ComfyUI 通道（REST + WS）、云端 RunningHub 通道（standard/plus 两档）、DSH 模型通道。
   **注意**：本地与云端支持**同样的五种 kind**（t2i/i2i/r2v/tts/music），差异只在跑在哪、计不计费、受什么约束。不要把云端写成「能力更强的一档」。
4. 本地档约束：CK 版本硬门槛 >= 0.2.36，版本比较只比前 3 段纯数字段（0.2.37rc1 保守判坏）；image 阶段**必须不带** CK 注意力（带了抛错并给可执行提示），video 阶段建议带（快 2.7×，没带只 warn）；AMD 默认每 3 次生成后调 /free，各 kind 都计入计数。
5. src/core/stages.js：四阶段固定顺序串行 llm→image→tts→video。
   - video **硬依赖** image：没有参考图直接抛错；
   - video **软依赖** tts：缺 voice_ref 降质但**必须在返回值/界面标出来**，不报错；
   - llm 与渲染阶段双向互斥；
   - 并发 video 1 / runninghub 1 / image 2；队列等待上限 120 分钟。
6. **显存门槛**：含 video 需 8GB，否则 4GB；不足**直接拒绝该阶段并说清差多少**。**不要实现自动拆批**（上游也没有），显存不够就明说不够。
7. 幂等与续跑：内容指纹只算**影响结果**的字段，命中就跳过（不重复生成、不重复计费）；只改依赖字段才重算；断点续跑不重跑已完成的。提示词改写最多 2 次且必须保留全部 __MINIMAX_H3_REF_N__ 占位符。
8. 音频分两件事：tts 音色设计（只有说话角色引用音色）与 music 背景音乐（整章），不要混。
9. 四个触发类工具 run_stage / regenerate_shot / assemble_chapter / rollback 一律走宿主 ask 人工授权。
10. workflows/specs/ 放 5 kind × local/cloud 的规格集，只存 roles/media/outputs/prune。
11. 产物字段（status / video_path / seed 等）**只有生成阶段能写**。

不做：ffmpeg 合成 / SRT / 交付物（T4）、右栏工作台与技能工厂（T5）、自动拆批、imageConcurrency / retryTimes 这类死配置、内置外部 CLI Agent、本地 HTTP 端点。
