## 2. 范围内

### 2.1 右栏工作台骨架（§10.2、§4.3）

注册在 **`sidebar.right.pane.tab`** 插槽，Tab **kind = `reelforge-workbench`**（F2，R8：**一经发布不可改名**）。

**外层骨架严格三层**（与 17 张界面稿的 560×900 结构一致）：

| 层 | 内容 | 约束 |
| --- | --- | --- |
| Header | 项目标题 / 副标 / 状态胶囊（**按屏变化**：胶囊 = 当前屏摘要） | 高 60 |
| StageBar | **6 步进度条**：需求 · 运行 · 方案 · 生成 · 分镜 · 交付 | 高 50 |
| **Scroll** | 主体内容，**唯一滚动容器**；成本行（已用 / 上限）在**本区底部** | `flex:1; min-height:0; overflowY:auto` |
| Footer | 常驻：**按屏变化**的「本屏标签 + 本屏主文案 + 本屏主按钮」 | 高 70 |

**滚动容器是硬规则（R7），不是排版偏好**：右栏 Tab 容器是 `overflow:hidden`，不自己建滚动容器就会出现「内容超高时底栏被裁掉且滚不到」。

```text
外层 section   height:100%; boxSizing:border-box; display:flex; flex-direction:column
  ├─ Header    flex:0 0 auto
  ├─ StageBar  flex:0 0 auto
  ├─ Scroll    flex:1; min-height:0; overflowY:auto   ← 唯一滚动容器
  │    └─ 内容层（左 20 / 右 540 的净宽 520）
  └─ Footer    flex:0 0 auto
```

**四条 UI 铁律（§4.3，违反即返工）**：

1. **禁止 iframe**——iframe 拿不到宿主主题 token、明暗切换和 `ctx.locale`。
2. **禁止 `require` 宿主 Client 包**（如 `@deepseek-ai/dsh-client-ui-primitives`）。正确做法：把 primitive 的 markup/CSS/行为**抄进插件自己的 `src/client/*.tsx` + `*.module.css`**，类名加插件前缀改名，**只保留 `--dsw-alias-*` token 引用**。
3. **样式一律用 `--dsw-alias-*` 主题 token**（`cordis_inspect_query` 的 `Theme` 列出清单）；字面颜色只允许出现在美术资源里。主题 token 被改名只会降级外观、不会破坏渲染 → 这是最低风险的对齐方式。
4. **不替换 app root，不往 `document.body` 追加第二个应用**；文本走 Client locale 服务。

**响应式按实测宽度判，不按窗口宽**（§4.3）：右栏永远全高、宽度 300–1150 随视口变。断点建议：

| 实测宽度 | 布局 |
| --- | --- |
| < 420px | 单列；两列网格降为一列；表格降为卡片流 |
| 420–899px | 单列为主，两列网格可用 |
| ≥ 900px | 两列网格启用（资产网格、分镜详情并排） |

> 设计稿按 **560px** 这个中位值画（§10.6.3 第 1 条）。窄端靠卡片降列，**不改画板比例**——560×900 的比例只属于设计稿，不属于运行时。

### 2.2 七个页签（§10.2）

**页签是 Tab 内部的二级分区**（segmented control），**不是开 7 个宿主 Tab**——宿主 Tab 持久化的是 kind，开 7 个 Tab 会占满右栏且每个都要独立加载。

| 页签 | 主要内容 | 对应画板 | 读什么 | 写什么 | 关键交互 |
| --- | --- | --- | --- | --- | --- |
| **章节** | 章节列表（标题 / 镜数 / 状态 / 成片时长）+ 每章阶段勾选（`llm`/`image`/`tts`/`video`）+「开始」 | `01-RF-Workbench`（章节进度区）、`06-RF-Stages` | 投影里的 chapters + stages | `run_stage`（**触发类，走 ask**） | 阶段勾选必须显示 **video 硬依赖 image / 软依赖 tts** |
| **分镜** | 逐镜卡片（缩略图 / 景别 / 运镜 / 时长 / 对白 / 状态）+ 选中镜详情 + 重生成 | `09-RF-Storyboard` | 投影里的 shots | `update_shot`（内容）/ `regenerate_shot`（**触发类，走 ask**） | 详情区显示**时长量化三选一**、**参考标签 `__MINIMAX_H3_REF_N__`**、装配顺序与上限 |
| **资产** | 10 类资产网格 + 变体挂载关系 | `08-RF-Assets` | 投影里的 assets | `create_asset` / `update_asset` / `bind_asset` | 分类筛选 10 类；变体（服装/年龄）显示 `parent_id` 挂载；参考图优先级 `服装 > 年龄 > 原图` |
| **上下文** | `bible`（人物圣经 + 站位表）/ `style`（风格指南）/ `continuity`（连续性记录）三栏 | `07-RF-Context` | 投影里的 context | `save_context` | 写入语义不同：**bible / style 整段覆盖、continuity 追加**——UI 必须给不同的确认文案 |
| **技能** | 技能列表（name / description / 来源 bundled·installed·generated）+ 正文预览 | `12-RF-Skills` | 技能扫描结果 | 安装 / 生成（§2.7） | 技能正文预览要显示**参考文件索引**；空 `description` 的技能**置灰并说明原因** |
| **成片** | 成片播放器（章节刻度 / 倍速 / 字幕音轨开关）+ 交付物下载 + 背景音乐库 | `10-RF-Player`、`11-RF-Deliver` | 投影里的 deliverables | `set_chapter_music`（内容）/ `assemble_chapter`（**触发类，走 ask**） | 播放器**按章刻度**（一章一集），不是单条时间轴 |
| **日志** | 变更日志 + 回滚按钮（单条 / 整批 / 按时间点） | `13-RF-Changelog` | T4 的变更日志读接口 | `rollback`（**触发类，走 ask**） | 漂移记录显示**「已漂移」黄条 + 强制回滚**；明示「媒体二进制不随回滚删除」 |

**页签共同纪律**：

- **每个页签都要有空态**（§2.3 的空态组件），且空态文案要说清「为什么空 + 下一步做什么」，不能只写「暂无数据」。
- **成本是常驻位**（§10.5）：已用金额 / 上限出现在**滚动区底部**（owner 2026-10-23 裁决 Q2，按设计稿 01 号板口径），不能只活在日志里。
- **状态从投影推导，不自建第二份状态**（R1）。UI 里的 `useState` 只能是**纯本地的交互态**（当前选中项、筛选条件、展开收起），**不能存业务数据**。
- 若 6 步进度条的判定需要新的枚举项，按 **F8 纪律先改 `src/core/constants.js` 再引用**，不得在 T5 的文件里另写一份。

### 2.4 对话里的 7 类结构化消息行（§10.3）

视图注册在 **`conversation.chat.node`** 插槽，**键为事件定义的 `kind`**。

| kind | 内容 | 形态 | 行内可做的操作 | 触发的工具 |
| --- | --- | --- | --- | --- |
| `reelforge-progress` | 阶段进度 + 当前章节 + 当前镜 | **轻量、可折叠** | 展开看明细 | 无（只读） |
| `reelforge-chapters` | 章节列表（可展开看单章状态） | 可展开 | 选中章节 | 无 |
| `reelforge-storyboard` | 分镜卡片（可展开看单镜） | 可展开 | 选中镜 / 看参考标签 | 无 |
| `reelforge-plan` | 执行路径选择器（**对话内直接改**） | 交互行 | 改 kind × 位置 | `update_plan`（走普通写路径，**不烧钱故不走 ask**） |
| `reelforge-assets` | 资产卡（人物/场景/道具） | 卡片行 | 展开变体挂载 | 无 |
| `reelforge-deliver` | 成片播放器 + 交付物列表 | 交互行 | 播放 / 单章下载 | 无（下载走 T4 产物） |
| `reelforge-changelog` | 变更日志 + 回滚入口 | 交互行 | 单条 / 整批 / 时间点回滚 | `rollback`（**触发类，走 ask**） |

#### 2.4.1 **不新增会话事件 `type`（R2）——本任务最容易犯的错**

上游 infinite-creation 的做法是往会话里 append 各种自定义事件类型。**ReelForge 不能这么做**：宿主拒绝未知 `type` 的事件（除非带 `ignorable: true`，而实时 `Session.append()` 设不了这个标记 → Session 会拒绝重开）。

**正确形态**：

- 7 个 kind **全部挂在已有的事件类型上**（`tool/result` 等），不新增 `type`。
- 事件定义走 `ctx.uiConversation.events.register()`，视图走 `conversation.chat.node` 插槽，**键 = kind**。
- 插件私有数据（进度快照、阶段耗时）**放存储服务**，不放会话事件（R2 的后半句）。

**自检方式**：注册前后各取一次会话事件 `type` 集合，**做差集必须为空**——这条要作为验收证据贴进报告。

#### 2.4.2 触发类判定

只有**会烧钱、占显存、破坏既有产物**的操作才走 `ask`（R4）：

| 行内操作 | 是否 ask | 理由 |
| --- | --- | --- |
| 改 kind × 执行位置 | ❌ 不 ask | 只是改方案，还没跑，不花钱 |
| 改分镜内容 | ❌ 不 ask | 写内容字段，可回滚 |
| 回滚 | ✅ ask | 覆盖既有内容，可能丢失后续改动 |
| 重生成单镜 | ✅ ask | 烧钱 |
| 合成章节 | ✅ ask | 烧显存 |

#### 2.4.3 行的可折叠性

`progress` / `chapters` / `storyboard` 三行**默认可折叠**，折叠态只留一行摘要（阶段 + 章节 + 镜号 + 耗时）。理由：对话是主战场，**折叠态是默认视图**；展开是用户主动要的。

#### 2.4.4 与 T4 的接缝：**文件所有权（并行任务不许改同一个文件）**

T4 也需要在对话里交付成片与变更日志。**两个任务同时改 `src/host/chatEvents.js` 必然冲突**。因此约定：

| 文件 | 所有者 | 内容 |
| --- | --- | --- |
| `src/host/chatEvents.js` | **T5** | 7 个 kind 的事件定义 + `conversation.chat.node` 视图注册 |
| `src/core/deliverPayload.js` | **T4** | `reelforge-deliver` 行的**纯数据组装** |
| `src/core/changelogPayload.js` | **T4** | `reelforge-changelog` 行的**纯数据组装** |
| `src/core/planPayload.js` | **T5** | `reelforge-plan` 行的数据组装 |

**冻结的 payload 形状**（T5 的视图按此读；T4 必须按此产出）：

```text
reelforge-deliver  →
  { chapters: [ { id, title, shotCount, durationSec,
                  deliverables: [ { kind, label, path, bytes } ] } ] }

reelforge-changelog →
  { entries: [ { id, at, summary, field, batchId?, drifted? } ],
    modes: ['single','batch','timepoint'] }

reelforge-plan      →
  { kind, position, provider?, candidates: [ { kind, position, sourceFile, label } ] }
```

> 若 T4 先落地且形状与此不同 → **T4 改形状，不 T5 改视图**。形状以本节为准（已作为 **F9** 记入 `00-总览.md` §3）。

### 2.5 快捷键（§10.4）

| 项 | 规定 |
| --- | --- |
| id | `dsh.reelforge.workbench`（必须匹配 R12 的 `/^[a-z][a-zA-Z0-9-]*(?:\.[a-zA-Z][a-zA-Z0-9-]*)+$/`） |

> `openTab` 在右栏没挂载会话时会抛 `no session surface is mounted`。**必须在 resolve 里先查再调**，不能靠捕获异常兜底。

### 2.6 工作流工厂：确定性解析（§8.3）

`src/core/analyzeWorkflow.js`——**纯逻辑、可单测**。

**四个常量（照抄）**：

| 常量 | 值 |
| --- | --- |
| `LOADER_CLASSES` | `LoadImage`→image/`image` · `LoadAudio`→audio/`audio` · `LoadVideo`→video/`file` · `UploadImage`→image/`image` |
| `SAVE_CLASSES` | `SaveImage` `SaveVideo` `SaveAnimatedWEBP` `VHS_VideoCombine` |
| `SAMPLE_CLASSES` | `KSampler` `SamplerCustomAdvanced` `KSamplerAdvanced` |
| `MODEL_LOADER_RE` | `/(UNET\|CLIP\|VAE\|Checkpoint\|Diffusion\|Lora\|ControlNet).*Loader\|Loader.*(Model\|CLIP\|VAE\|UNET)/i` |

**推导规则（照抄）**：

| 目标 | 规则 |
| --- | --- |
| `positive_prompt` | 第一个 `inputs[field]` 为字符串且 `field ∈ {text, prompt}` 且未被负向正则命中的节点 |
| `negative_prompt` | 同上，但 title/field 命中 `/neg\|negative\|负向\|负面/` |
| `width` / `height` | 第一个 `class_type` 以 `Empty` 开头且含 `Latent`，或同时有 `width`+`height` 且 class 含 `Latent` |
| `seed` | ① sampler 或含 `Noise` 的节点上的 `seed`；② 否则第一个 `noise_seed` |
| `filename_prefix` | 第一个 save 节点 |
| `seconds`/`resolution`/`aspect_ratio` | **仅当**全图存在这三者之一时才填 |
| `image` | 第一个 image loader |
| `kind` | 含 `SaveVideo` 或有 video fields → `r2v`；否则有 image loader → `i2i`；否则 `t2i` |
| `outputs` | 所有 save 节点的 `class_type` 数组 |
| `diagnostics` | `{loaders, modelLoaders, saves, samplers, sizeNodes, textCandidates, hasVideoFields}` |

**输出必须符合 F5 的 `WorkflowSpec` 形状**：`{id, kind, name, description, sourceFile, roles, media?, outputs, prune?}`——其中 `roles` 由推导结果组装成 `{node, field, map?}` 数组。

**两个必须照抄的边界**：

- **`media` 恒为 `null`，`prune` 不推导**——`analyzeWorkflow` 的返回体里**没有 `prune` 字段**。媒体绑定由上层补，剪枝靠「从 outputs 反向可达性裁剪」自动解决（T3 负责）。
- **UI 必须展示 `diagnostics`，不能只说「导入成功」**。解析不出来就摆出 `loaders` / `saves` / `samplers` / `textCandidates` 的实际命中情况，让用户看得见「这个工作流里到底有什么」。

### 2.7 技能生成与安装（`generated` 来源，§8.2）

技能来源三档：`bundled`（插件自带）/ `installed`（用户装的）/ `generated`（生成的）。

#### 2.7.1 **不搬上游「LLM 起草 SKILL.md」路径**

上游 README 与根 `SKILL.md` 写着「上传工作流 → 自动生成技能」，但**当前 main 分支代码里没有这条路径**：没有工作流导入路由、没有 `import_workflow` 工具、没有调用 LLM 生成 `SKILL.md` 的代码。README 描述与代码**不符**。

**ReelForge 的做法**（自研，不复刻）：

1. `analyzeWorkflow()` 产出**解析结果 + diagnostics**（§2.6）。
2. **由 DSH 对话里的模型**按同一模板起草 `SKILL.md` 正文——DSH 本来就是 Agent 运行时，模型能力是现成的，没必要再内置一个 Agent 内核。
3. **插件只做两件事：格式校验 + 落盘**。起草质量不归插件管，插件只保证「落盘的技能能被引擎正确读到」。

#### 2.7.2 安装/生成时的**格式校验**（这些是硬门槛，不是提示）

| 校验 | 规则 | 不通过怎么办 |
| --- | --- | --- |
| frontmatter 存在 | `---` 包裹的块必须能匹配 | **拒绝安装** |
| `name` | 事实上必填 | 缺省用目录名兜底**但不报错**（与上游一致），但要在 UI 上标黄 |
| `description` | **空串会让路由与技能目录双双失效** | **拒绝安装**（不是警告） |
| 技能名安全 | 拒绝 `/` `\` `:`、绝对路径、`.` `..` | **拒绝安装**（防 `path.join` 逃出技能目录） |
| 多行标量 | frontmatter 解析器只识别单行标量，多行 `description: >` 会失配 | 解析器**要么支持折叠标量、要么安装时规范化**；ReelForge 选后者——**安装时规范化成单行** |
| `SKILL.cn.md` | **优先于** `SKILL.md` | 两个都存在时只取中文版 |

#### 2.7.3 落盘位置与来源标记

- `generated` 技能**不写进插件包的 `skills/` 目录**（那是 bundled 的地盘，且 `lib/` 在 npm `files` 里，写进去会被 `npm pack` 带走）。落盘到**插件自有存储**或工作区，用户可导出。
- 生成/安装后：能出现在**技能目录**（name + description + whenToUse）、能被 `skill(name)` 读到、能被 `skill_reference(name, ref)` 取到参考文件。
- **许可边界**：插件**不分发**第三方技能正文、`vendor/` 代码、ComfyUI 模板（§2.4 许可）。用户自行安装上游技能包；`generated` 来源只允许装**用户自备**的技能。

#### 2.7.4 技能包体积上限

用户上传技能包时按 `SKILL_ZIP_MAX_BYTES = 20MB` 拒绝超限；参考图等二进制另有 `UPLOAD_MAX_BYTES` 分档（图片 20MB / 音频 100MB / 视频 500MB）——这两个常量在 T1 的 `constants.js` 里，**不得另写一份**。

### 2.8 client bundle 纪律（R9、R10）与共享状态（R14）

#### 2.8.1 R9：第三方库必须整包内联

client bundle 的 `require` 受 **purity gate** 限制 → 第三方库**整包内联**进本插件产物，不得 externals、不得从宿主 client 包 import。**这与 §2.1 铁律 2 是同一条纪律的两面**：既不能 require 宿主包，也不能指望宿主提供第三方库。

#### 2.8.2 R10：分片加载

| 规则 | 说明 |
| --- | --- |
| 入口**异步**加载 | `require.async('./client.<名字>.js')`——**同步 `require` 会把分片拉回入口，体积白拆** |
| 分片名正则 | `^client\.[A-Za-z0-9][A-Za-z0-9._-]*\.js$` |
| **同一 rev** | 分片与入口**必须同一 rev**，rev 用错直接 404 |
| **旧分片必须手工删** | `lib/` 在 npm `files` 里 → 构建脚本不再产出的旧分片**必须手工删掉**，否则 `npm pack` 会把残骸带走 |

**建议分片**（名字全部匹配上面的正则）：`client.workbench.js`（工作台主壳）+ 按页签切 `client.chapters.js` / `client.shots.js` / `client.assets.js` / `client.context.js` / `client.skills.js` / `client.player.js` / `client.changelog.js`，另加 `client.chatrows.js`（对话行视图）。

> 分片是**性能手段，不是目标**。若实测首屏没收益，可以只留 `client.workbench.js` 一个分片——但 R10 的四条规则（异步 / 正则 / 同 rev / 删旧片）**一条都不能破**。

#### 2.8.3 R14：两个 Tab 共享状态用模块级单例

若实现可选的第二个宿主 Tab（kind `reelforge-runs`，历史运行与成本记录，§10.2），它与 `reelforge-workbench` **共享同一批数据**。此时：

- 共享状态放**模块级单例** + `useSyncExternalStore`，**不能放组件 `useState`**。
- 单例**只存派生视图**，不存业务事实——业务事实仍在会话投影里（R1）。单例是**订阅通道**，不是**事实源**。
