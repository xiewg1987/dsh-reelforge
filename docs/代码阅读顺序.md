# 代码阅读顺序（审核用）

> **这份文档给谁**：要审核这个插件代码的人（owner / 复核者）。
> **怎么用**：下面有三条路线 —— 15 分钟摸边界、2 小时看主干、按需求跳。
> 行数是 **2026-10-24 快照**，只作量级参考，以文件实际内容为准。

---

## 0. 一句话架构

**ReelForge 是一个 DSH 插件**：宿主半（Node）注册 15 个工具给模型调，客户端半（浏览器）渲染右栏工作台；
两边靠**一条投影**（`reelforge/project`）同步，投影**只从会话日志 fold 出来**（R1：日志是唯一事实源）。

```
模型调工具 ──▶ 宿主半 src/host/tools/（7 个文件）
                    │  产出 meta.reelforge.patches（状态补丁）
                    ▼
              会话事件 session/event
                    │  fold
                    ▼
        src/host/projection.js ──▶ wire view ──▶ /api/reelforge.state
                    │                                      │
                    │                                      ▼
                    │                        客户端 RF.store（useSyncExternalStore）
                    │                                      │
                    └──────── 4 条只读路由 ◀────────────────┘
                        .state / .capabilities / .probe / .file
```

**四条路由**（`src/host/apply.js` 里注册，全部在 Connection 认证通道内）：

| 路由 | 是什么 | 注意 |
| --- | --- | --- |
| `/api/reelforge.state` | 会话投影的 wire view | 唯一的数据同步通道 |
| `/api/reelforge.capabilities` | Config 归一化后的可调值 | **只读**：插件没有写配置的通道 |
| `/api/reelforge.probe` | 环境探测报告 | **不进 wire view**（能力事实，不是会话状态）；30s 缓存 |
| `/api/reelforge.file` | 交付物下载 / 视频播放 | 路径必须过越界防护 |

## 1. 仓库地图：谁是**真源**，谁是**产物**

```
dsh-reelforge/
├─ index.js                 插件入口（把 apply 交给宿主）
├─ client.js                ⚠️ 产物 —— 由 build-client.mjs 生成，**禁手改**
├─ cordis.patch.yml         宿主装载清单；config 块 = 用户可调的值
├─ patch.dev.yml            宿主源码联调用（**不加载**客户端半）
├─ package.json             零运行时依赖；files 已排除 __tests__
├─ locale/{zh,en}.json      ⚠️ 产物 —— 由 src/client/locale.js 同步生成
│
├─ src/core/      20 个文件  纯业务规则：零 ctx、零 IO、可单测
├─ src/host/      22 个文件  宿主装配：工具 / 路由 / 投影 / 闸门 / 存储
│  └─ tools/      7 个文件   15 个工具的定义（薄壳 `src/host/tools.js` 只 re-export）
├─ src/client/    16 个文件  浏览器半片段（挂在一个 RF 命名空间里）
│  └─ workbench/   8 个文件  工作台壳层 + 10 块屏 + RF7 零件 + 样式
├─ src/media/      4 个文件  ffmpeg 合成 / 字幕 / 交付物落盘
├─ src/skills/     3 个文件  技能目录扫描 + 技能工具
├─ src/workflows/  5 个文件  ComfyUI / RunningHub 通道 + 规格解析
│
├─ workflows/      规格 JSON（t2i / i2i / r2v / tts / music）+ fixtures
├─ skills/         技能正文（SKILL.md）
├─ scripts/        9 个门禁与工具脚本
├─ design/         RF7 设计稿真源（FigCraft 主稿 + 18 板 PNG/SVG + 建稿脚本）
├─ docs/开发任务/   5 份任务书 + 实机原始记录（**验收门禁的输入**，必须进版本库）
└─ .github/workflows/ci.yml   CI（12 步）
```

**三条"真源"**（改动只允许发生在这里，其余地方只能**引用**）：

| 真源 | 谁是它的镜像 | 门禁 |
| --- | --- | --- |
| `src/core/constants.js`（枚举 / 工具 id / 限额） | `src/client/manifest.js` | F8：逐项比对，不一致就红 |
| `src/client/locale.js`（文案键） | `locale/{zh,en}.json` | `npm run sync:locale` |
| `src/client/**`（客户端源码） | `client.js` | `npm run build:client` + CI 漂移检查 |

## 3. 审核清单（逐条查，每条都给了落点）

| # | 检查项 | 去哪看 | 判坏的样子 |
| --- | --- | --- | --- |
| 1 | 枚举有没有第二份？ | `src/core/constants.js` vs `src/client/manifest.js` | 界面下拉自己写了一份画幅表 |
| 2 | 文案有没有硬编码在组件里？ | `src/client/**` 搜中文字面量 | 组件里直接写「已通过」而不是 `t('rf7.runGate.pass')` |
| 3 | `client.js` 是手改的吗？ | `git log -- client.js` | 改了 `src/client/**` 却没跑 `build:client`（CI 第 12 步会抓） |

| 6 | 只读屏的按钮是死按钮吗？ | `src/client/workbench/flow.js` | 能力还没接上却给了一个可点的按钮（要么接工具，要么禁用 + 说清缺什么） |
| 7 | 数字加得起来吗？ | 屏内汇总 / 顶部胶囊 / 底栏 | 胶囊写「6 / 9 通过」、屏里写「6 项检查」（两处各算一次就必然对不上） |
| 8 | 有没有编内容？ | 各屏空态 | 没有探测结果却铺一行行「未配置」 |
| 9 | 阶段前置条件齐吗？ | `src/core/probe.js` 的 `STAGE_PROBE_REQUIREMENTS` | 某阶段少列一项硬依赖 |
| 10 | 触发类工具都走 ask 闸门了吗？ | `src/host/apply.js` 的 `tools/pre-execute` | 消耗算力/费用的工具没被拦 |
| 11 | 路径越界挡住了吗？ | `src/host/workspace.js` | `../../etc/passwd`、绝对路径、Windows 盘符、UNC 任一放行 |

## 4. 改代码前必读的 7 条硬规矩

1. **零 npm 运行时依赖** —— 只能用 node 内置模块。要加依赖前先问「能不能不依赖」。
2. **`client.js` 是产物** —— 改 `src/client/**` 后必须 `npm run build:client`。
3. **文案唯一来源是 `src/client/locale.js`** —— 改完跑 `npm run sync:locale`（zh/en 键集合必须一致）。
4. **`src/core/` 里不能出现 `ctx`** —— 那是宿主专属逻辑的边界，`src/core/` 要保持纯函数、可单测。
5. **探测结果不进会话投影** —— 它是能力事实，走独立只读路由。
6. **`deps`（能力通道客户端）只能插件侧注入** —— R8 门禁明确排除 `deps`，改 `cordis.patch.yml` 塞它会被判「多余键」。
7. **测试目录不在版本库里**（owner 决定）—— 本地跑 `npm test`；CI 上那两步会判「跳过」。

## 5. 已知缺口与存疑（审核时重点看这几处）

| 处 | 现状 | 影响 |
| --- | --- | --- |
| `deps.probe.comfy` / `deps.probe.llm` | 宿主**还没注入**这两个通道客户端 | 启动检查屏的「ComfyUI 服务」「LLM 接口」两行恒为「未通过」（面板如实显示缺什么，不是撒谎，但功能没接上） |
| T5 A40 验收措辞 | 任务书写「7 行固定检查清单（含 Agent 行）」，实现是「6 行检查项 + Agent 运行时单列说明（不计入检查项）」 | 验收条目与实现口径不一致，**待 owner 拍板**：改条目还是改实现 |
| 实机证据 | `docs/开发任务/实机/dsh-0.2.1-alpha.1.md` 记的是**旧行为**（含 CK 版本单列行）；T5 A4 / A19 / A27 三条实机事实缺失 | 验收门禁恒有 3 个缺口 ⇒ **CI 一直红**，直到重采实机证据 |
| CI 的覆盖率 | 仓库里没有测试文件 ⇒ 干净 clone 采不到覆盖率 | `verify:coverage` 在 CI 上判「跳过」（退出 0）；覆盖率门槛实际由**本地**那条命令守着 |
| `src/host/stageBridge.js`（825 行） | 最大的单个文件，没拆 | 改动它的回归面最大，改之前先跑相关子集 |

## 6. 命令速查

```powershell
cd D:\Code\WebCode\dsh-reelforge

npm run build:client       # 重建 client.js（内容没变会输出 unchanged）
npm run sync:locale        # locale/{zh,en}.json 跟随 src/client/locale.js
npm run sync:dsh           # 同步进 ~/.dsh/profiles/web
npm run check:identity     # R7 包名三处一致
npm run verify:bundle      # 装载验证（25 项）
npm run typecheck          # JSDoc 类型检查
npm run verify:coverage    # 覆盖率门槛（本地才有意义）
npm run verify:acceptance  # 验收门禁（122 项，逐条核对实机证据）

# 只跑受影响的那几个测试文件（不要默认跑全量）
node --test src/client/__tests__/flow.test.js
node --test src/core/__tests__/*.test.js
```

改完客户端后的完整生效链：`build:client` → `sync:dsh` → **重启宿主**（boot 时快照 client.js）→ 浏览器 Ctrl+F5。
