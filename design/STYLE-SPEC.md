# ReelForge 设计稿样式规范 v4（桌面端面板）

> **v2 变更**：v1 用 380×920 的细长画板，那是**手机竖屏比例**，与产品形态不符。
> ReelForge 是 DSH 的**桌面端右栏面板**（宽 300–1150px、永远全高），v2 统一为 **560×900**。
> 9:16 是**成片的画幅属性**，不是 UI 形态 —— 界面里不再出现细长手机画板。
>
> **v3 变更**：新增 `RF/RunMode` 与 `RF/DeviceCheck` 两页，界面稿 13 → 15 张；
> 顶栏 StageBar 由 **5 步扩为 6 步**（需求 · 运行 · 方案 · 生成 · 分镜 · 交付）。
>
> **v4 变更**：参照源换成 `SwotAtmk/infinite-creation`，界面稿 15 → **17 张**。
> 新增 `RF/Stages`（四阶段勾选）、`RF/Context`（三栏上下文）、`RF/Skills`（技能）、`RF/Changelog`（变更日志与回滚）；
> 删除 `RF/Runs`（历史运行被「日志」页吸收）；原 12–15 顺延为 14–17。
> **StageBar 仍是 6 步**（结构与坐标完全不变），只有当前步与计数随画板变（见 §4）。
> 栅格 / 颜色 / 字体规则**全部不变**。

## 0. 画布规格（唯一标准）

| 类别 | 尺寸 | 用途 |
| --- | --- | --- |
| 界面画板 | **560×900** | 全部 17 张界面稿，**尺寸完全一致**，不因内容多少改变 |
| 架构图 | **1200×700** | 2 张示意图，宽幅，与界面稿明显区分 |

**为什么是 560**：§4.4 R7 规定右栏宽度区间 300–1150px。560 落在区间中位，是桌面应用侧栏的典型值；900 是常见桌面窗口内容区高度（1080 减去标题栏/工具条）。**这个比例（0.62）一眼是桌面面板，不是手机。**

## 1. 栅格

| 规则 | 值 |
| --- | --- |

| 通栏卡片 | `x=20, width=520` |

| 描边 | 1px `stroke="#23262B"` |

## 2. 颜色令牌（不变）

`BG #0B0E14` · `SURFACE #171A20` · `SURFACE-2 #12151B` · `SURFACE-3 #1F2127` · `LINE #23262B` · `LINE-2 #2D3035` · `TEXT-1 #F2F5F9` · `TEXT-2 #8A93A5` · `TEXT-3 #5B6472` · `ACCENT #4C8DFF` · `ACCENT-DIM #16203A` · `OK #3FB950` · `WARN #D29922` · `WARN-SURF #2A2214` · `ERROR #F85149` · `ERROR-SURF #2A1618` · `WHITE #FFFFFF`

**只用不透明预混色，禁止 `opacity`**（FigCraft 导入 SVG 不保证透明度）。

## 3. 字体（不变）

`Noto Sans SC` 15 / 13 / 12 / 11 / 10；`Inter` 10–12 用于纯 ASCII（SCENE / SHOT / 编号 / 耗时 / 码率）与全大写英文小节标签（加 `letter-spacing="1"`）。
**基线规则**：`y` 是基线；文字顶边在 `top` → `y = top + fontSize`。

## 7. SVG 硬性要求

1. 只用 `<rect>` `<circle>` `<polygon>` `<text>`；禁 `<line>` `<path>` `<g>` `<defs>` 渐变 滤镜 `<image>` `opacity` `transform`。
2. 第一个元素是铺满画板的背景 rect。
3. 文字不换行（SVG 无自动换行），太长就改短或改字号。
4. `text-anchor="end"` 可用；`letter-spacing` 仅用于全大写英文标签。
5. 圆角只用 `rx`（统一半径）；不混用不同角半径。
6. UTF-8、**无 BOM**、第一个字符就是 `<svg`、不写 XML 声明。
7. 文件名 = `序号-RF-画板名.svg`，画板名去掉 `.svg` 后即 FigCraft 画板名（`RF/Plan` → `05-RF-Plan.svg`）。
   架构图例外：`ARCH-三平面架构.svg` / `ARCH-生成流水线.svg`，尺寸 **1200×700**（不适用 560×900 的越界规则，
   但颜色 / 字体 / 禁用元素规则完全相同）。
8. **内容不得越过 y=826**：底栏（Footer）顶在 830，且 Footer 矩形最后画，越界文字的降部会被盖住。
9. **卡片内元素离卡片边留 12px**：贴死描边会看起来像被边框切了一刀（`check-inset.mjs` 会报）。
10. **先画矩形再画它的文字**：后画矩形会盖住已画文字，文字直接消失（`check-overlap.mjs` 会报）。

## 8. 交付前自检

- [ ] `width="560" height="900" viewBox="0 0 560 900"`
- [ ] 没有任何元素越界：`x + width ≤ 560`，`y ≤ 900`
- [ ] 内容左右边界落在 20 … 540
- [ ] 文字无重叠（右对齐列、卡片内多行，基线间距 ≥ 18）
- [ ] 颜色/字号全部来自 §2 §3
- [ ] 没有 `<image>` / 渐变 / 透明度 / transform
- [ ] StageBar 是 6 步，步名顺序为「需求 · 运行 · 方案 · 生成 · 分镜 · 交付」，计数 `N / 6`（§4）
- [ ] 内容未越过 y=826
- [ ] `check-svg.mjs` / `check-inset.mjs` / `check-overlap.mjs` 三项全 PASS（空输出即通过）
- [ ] 用 headless Chrome 渲染一遍目视复核（这是硬要求，不是可选项）
